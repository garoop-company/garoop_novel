# Garoop Bunko ― 文庫小説の執筆と追加

> ⚠ **データの本拠地は移動済み**: 小説の JSON は `garoop_novel/src/data/` から **`garoop-data/public/novel/`** に移動しました。新刊を追加する時は **garoop-data リポジトリの `garoop-novel-content` スキル**（`/Users/yamashitadaiki/git_work/garoop-data/.claude/skills/garoop-novel-content/SKILL.md`）を使ってください。本ファイルは旧仕様の参考として残しています。garoop_novel 側で執筆作業を続けないこと。

このスキルは、Garoop Novel リポジトリに、文庫小説 1 巻（章）を追加するための手順とお作法をまとめたもの。短編ではなく、**読み応えのある長編 1 話**を 1 巻として扱う。

## 起動条件
- 「Garoop Novel に○○の小説を書いて」「ガロープ文庫に追加して」と頼まれた時
- 既存シリーズ（人物列伝 / 長崎物語）の続編エピソードを依頼された時
- 新シリーズの第 1 巻を依頼された時

## 既存の世界観（前提）

- サイトのトーンは「夜の文庫」「書架」「明朝・蝋燭・蔵書票」。CTA も「文庫を開く」「頁をめくる」など書物の語彙を使う。
- ノベル本文は明朝系で表示され、読書の伴走者「ガルちゃん」がページ毎にコメントを添える（`companionLines`）。
- 既存シリーズと既出キャラ:
  - **人物列伝 / shimizu-tax** — カマクラウドの税理士・清水小綾（鎌倉）。事務所は由比ヶ浜近くのレトロビル二階。哲学は「数字の裏側にある物語」「税理士は人生の伴走者」。
  - **人物列伝 / suda-sharoushi** — オール社会保険労務士・須田朋美。両親の工場倒産が原点。「制度は人を縛るためじゃない、守るためにある」。
  - **人物列伝 / yamashita-garoop** — 株式会社 Garoop 代表・山下大貴。長崎の坂の街で創業。生成 AI とエンタメの融合、ガルちゃん、出島の精神。
  - **長崎物語 / nagasaki-monogatari** — 街そのものを主役にしたエッセイ風。出島・市電・卓袱・浦上など切り口を一つに絞る。

新シリーズを追加する時は、上記との重複を避け、新しい `seriesKey` と必要なら新カテゴリを定義する。

## ファイル構成

| 役割 | パス |
|---|---|
| 小説メタデータ一覧 | `src/data/novels.json` |
| 章本体（pages + companionLines） | `src/data/chapters/<id>.json` |
| 読書ビューア（UI 側、編集不要が原則） | `src/app/[lang]/novels/[id]/ClientNovelView.tsx` |
| 読み込みロジック | `src/app/[lang]/novels/[id]/page.tsx` |

## 章ファイル（chapters/<id>.json）の必須スキーマ

```jsonc
{
  "id": "<seriesKey>-<NNN>",      // 例: "shimizu-tax-005"
  "pages": [
    "1ページ目の本文（~400〜600 文字、地の文中心、改行なし、句点で締める）",
    "2ページ目の本文",
    "..."
  ],
  "companionLines": [
    "1ページ目に対応する、ガルちゃんの一行コメント",
    "2ページ目..."
  ]
}
```

- `pages` と `companionLines` は **同数（基本 8）**。`companionLines` を空にしない。揃わないとビューア側で配列の循環参照が起きるので必ず揃える。
- 末尾に空文字列 `""` を入れない（過去にやりがち）。
- ファイル末尾は改行 1 つで終える。JSON のシンタックスは厳密に。

## 本文（pages）の作法

- **長さ**: 1 ページあたり日本語で **400〜600 字程度**を目安に。短すぎると文庫らしさが出ない、長すぎると 1 ページとして重い。
- **構成**: 8 ページで「導入 → 展開 → 山場 → 余韻」がゆるく描かれるように設計。エッセイ・ドキュメンタリー風でも、登場人物の独白でも可。
- **文体**: 明朝で読まれることを意識した、句読点多めのリズム。地の文と独白を混ぜる。「――」「『』」を活用。
- **固有名詞**: 鎌倉・長崎の地名・店名は積極的に。架空のお店を出してもよいが、実在の街並みと矛盾しないこと（例: 鎌倉なら由比ヶ浜・小町通り・江ノ電、長崎なら稲佐山・出島・浦上・市電）。
- **登場人物の言行**: 既出キャラ（小綾・朋美・山下）の哲学・口癖・原体験は SKILL.md の上記サマリと矛盾させない。
- **避ける表現**: 過剰なエンタメ装飾、絵文字、英語スラング。「！」の連打。説明的すぎる解説（読者を信じる）。

## companionLines の作法

- **長さ**: 1 行 15〜30 字程度の短いつぶやき。
- **役割**: 読者の隣でガルちゃんが読んでいる体。共感、軽い驚き、感想、自己投影。
- **トーン**: 親しみのある関西的・くだけた口調も OK。「〜だね」「〜だよね」「うんうん」「泣ける」「ぐっとくる」「行ってみたい」など。
- **ネタバレ**: しすぎない。先回りで結末を漏らさない。
- **絵文字**: 使うなら控えめに（「!」止まりが基本、☆ や 🎉 は最終ページに 1 つ程度）。

## novels.json への追加

`src/data/novels.json` は配列。新巻 1 つにつき 1 エントリを末尾追加（カテゴリでまとめてある場合はカテゴリ末尾）。

```jsonc
{
  "id": "<seriesKey>-<NNN>",                 // chapters/<id>.json の id と完全一致
  "seriesKey": "<seriesKey>",
  "episodeNumber": <整数>,                    // シリーズ内通番。1 から始める
  "title": "○○ ― サブタイトル",                // 「親シリーズ ― 副題」のフォーマットを推奨
  "description": "1〜2 文の引き。140 字以内目安",
  "category": "人物列伝" | "長崎物語" | "<新カテゴリ>",
  "chapterFile": "<id>.json",
  "pageCount": 8,
  "animationPreset": "book-classic",
  "keywords": "カンマ区切りの SEO キーワード（人物名・地名・テーマ語）",
  "lang": "ja",
  "createdAt": "YYYY-MM-DD"                  // 当日。曖昧な日付は使わない
}
```

注意点:
- **id の一意性**: 既存と被らないこと。同じ `seriesKey` 内では `episodeNumber` を連番に。
- **多言語**: 当面は `lang: "ja"` のみ。読み込みロジックに ja → 任意ロケールのフォールバックがあるので、他言語ロケールでも JA 版が読める。多言語化は別タスク。
- **category**: 新規作成は慎重に。同テーマなら既存カテゴリに寄せる。

## 既存シリーズの続編を書く時のチェック

1. `src/data/novels.json` で同じ `seriesKey` の既存巻を確認し、`episodeNumber` の最大値 +1 を採番。
2. 既存章 `chapters/<seriesKey>-001.json` 〜 を読み、登場人物の口癖・舞台設定・既に書かれたエピソードと重ならないようにする。
3. 既出のテーマを「別の角度」で書く（例: 朋美の「聴くという仕事」を一巻目で書いたら、二巻目はより具体的な事件、三巻目は法改正対応、など）。

## 新シリーズを始める時

1. `seriesKey` を決める（短い英小文字＋ハイフン、テーマが分かるもの）。
2. `category` を決める。既存のものに収まらない時のみ新設。
3. 第 1 巻は **そのシリーズの世界観を立ち上げる役** を担うので、登場人物のバックストーリーや原体験を書き、後の巻で参照できるアンカーを置く。

## 検証

新規巻を追加したら、必ず:

```bash
npm run build
```

を走らせる。`build --webpack` で全静的ページ（17 巻 × 7 ロケールなど）が生成される。エラーがあれば `npx tsc --noEmit` で型エラーを確認。

`src/app/[lang]/novels/[id]/page.tsx` の `generateStaticParams` が `novels.json` の全 ID × 全ロケールを展開するので、ビルド成功＝最低限のリンク・ロード経路が通っている証拠になる。

## このスキルでやらないこと

- UI コンポーネント（ClientNovelView, page.tsx）の改修 — 必要が出たら別作業として行う。
- 多言語翻訳 — 当面 ja 単独。
- 旧 `garu-detective`, `garu-intelligence`, `garu-entrepreneur`, `garu-genai`, `garu-family` 系の章追加 — これらは旧シリーズで novels.json から外してある。orphan の章ファイルを参照してはいけない。
- 実在の人物（清水小綾・須田朋美・山下大貴）の発言として、本人が言っていない政治的・宗教的・差別的な発言を書くこと。あくまで前向きな職業紹介・人物列伝として描く。

## 進め方の典型

1. ユーザーから題材を受ける（「○○について」「△△の続編を」）。
2. 既存 `novels.json` と関連章を読み、シリーズ・既出設定を把握。
3. 8 ページ分のあらすじを頭で組み立てる。書き出す前に、ページごとの一行サマリ（導入／展開／山場／余韻）を考える。
4. `chapters/<id>.json` を Write ツールで作成。
5. `novels.json` に新エントリを追加（既存配列の末尾またはカテゴリ末尾）。
6. `npm run build` で検証。
7. ユーザーに何を追加したか、ファイルパスのリンク付きで報告。複数巻まとめて追加した時は箇条書きで一覧化する。
